# What does the 'dependencies' keyword do and how does it control artifact passing between jobs?

**Difficulty:** Intermediate · **Levels:** Fresher, SDE-1/2, SDE-2/3 · [↑ Cache vs Artifacts](<../../../../TOOLS/GitLab/GitLab_CI/Cache_vs_Artifacts.md>)

## Answer

Summary: In GitLab CI, the dependencies keyword is used to define dependencies between pipeline jobs. This ensures that a job cannot start before its dependent jobs have successfully completed. We will explore how this keyword works, its syntax, and best practices for using it.

#### Triage
The question asks about the dependencies keyword in GitLab CI and how it controls artifact passing between jobs. Essentially, we need to understand:

What dependencies does.

Best practices for using dependencies.

Key Assumptions:

We assume a basic understanding of GitLab CI pipeline concepts.
We will discuss both single and multi-stage pipelines.

Step-by-Step Solution:

Understanding Dependencies in GitLab CI: The dependencies keyword is used within the .gitlab-ci.yml file to specify which jobs must complete successfully before a given job can start. This ensures that dependencies are met, and resources or artifacts generated by one job are available for another.

Syntax Example:

YAML
stages:
  - build
  - test

frontend-build:
  stage: build
  script:
    - npm install
    - npm run build
  artifacts:
    paths:
      - dist/

backend-test:
  stage: test
  dependencies:
    - frontend-build
  script:
    - pytest

How Dependencies Work:

In the above example, backend-test depends on frontend-build. The pipeline will not start executing the backend-test job until frontend-build has successfully completed.
If any of the dependencies fail or are marked as unstable, the dependent jobs will not run.

Artifact Passing: Artifacts generated by frontend-build (e.g., files in the dist/ directory) can be used as inputs for backend-test. This is achieved through the use of artifacts and dependencies.

Best Practices:

Use dependencies to enforce a logical order of job execution.
Clearly define which jobs depend on others, making the pipeline easier to understand.
Manage artifact lifecycle by cleaning up unnecessary data to reduce storage usage.

#### Common Mistakes
and Follow-Ups:

Forgetting to add dependencies when needed can lead to broken pipelines or incorrect job execution flow.
Not properly managing artifacts can result in redundant builds or wasted resources.
Misunderstanding the behavior of dependencies with artifacts, leading to unexpected issues.

#### Closing Summary
In GitLab CI, the dependencies keyword ensures that a job will only run after its dependent jobs have completed successfully. This is crucial for maintaining pipeline integrity and ensuring that downstream tasks can use the correct artifacts. Best practices include clearly defining dependencies and managing artifacts effectively.

#### Common Mistakes

Overusing or underusing dependencies.
Ignoring artifact management, leading to inefficient pipelines.
Not testing dependency conditions thoroughly during development and staging environments.
