# What is the difference between artifacts and cache in GitLab CI?

**Difficulty:** Intermediate · **Levels:** Fresher, SDE-1/2, SDE-2/3 · [↑ Cache vs Artifacts](<../../../../TOOLS/GitLab/GitLab_CI/Cache_vs_Artifacts.md>)

> ⚠️ Practice answer, not verified. Some answers contain mistakes; when in doubt, follow the lesson.

## Answer

In GitLab CI, both artifacts and cache serve crucial roles but with different purposes. Artifacts are used to preserve and share build results or generated files across jobs and pipelines, whereas cache is designed to optimize the performance of your pipeline by reusing existing artifacts from previous runs. Let's break down each concept in detail.

#### Triage
Understanding the Question

The question asks us to differentiate between artifacts and cache. This is important because both concepts play a vital role in optimizing CI/CD pipelines, but they serve distinct purposes. Artifacts are primarily about sharing data and results, while cache focuses on improving efficiency by reusing work.

#### First-Principles Solution
Artifacts

Artifacts in GitLab CI refer to the files or resources that your jobs produce during a pipeline run. These can include build outputs, tests reports, or any other relevant files you wish to preserve and share across different stages of your pipeline or even with external teams. Configuring artifacts ensures that these important results are stored and accessible for future reference.

To use artifacts in GitLab CI, you specify them in the .gitlab-ci.yml file under each job:

YAML
job_name:
  script:
    - make
  artifacts:
    paths:
      - build_output/

This configuration ensures that the build_output/ directory is stored and can be accessed by downstream jobs or manually downloaded.

Cache

Cache in GitLab CI, on the other hand, involves storing the contents of a job's working directory between pipeline runs. This means if certain files remain unchanged, they are reused from previous runs, which can significantly speed up your pipeline execution time.

To use cache, you specify it similarly to artifacts:

YAML
job_name:
  script:
    - make
  cache:
    key: "v1"
    paths:
      - build_output/

The cache directive allows you to specify a unique identifier for the cache and define which files should be cached.

#### Closing Summary
+ Common Mistakes/Follow-Ups

In summary, artifacts are used to preserve and share important data generated by your pipeline runs, while cache optimizes performance by reusing existing files from previous pipeline executions. Both concepts can significantly enhance the efficiency and reliability of your CI/CD processes.

#### Common mistakes
include:

Not specifying the correct paths for artifacts or cache.
Overlooking the need to clear old caches manually if changes are made.
Misconfiguring cache keys, leading to unnecessary re-executions.

might involve discussing specific scenarios where using both concepts together can optimize a pipeline further, or exploring more advanced caching strategies like shared caching across multiple jobs or pipelines.
