# What are artifacts in GitLab CI and why would you need them between jobs?

**Difficulty:** Basic · **Levels:** Fresher, SDE-1/2, SDE-2/3 · [↑ Cache vs Artifacts](<../../../../TOOLS/GitLab/GitLab_CI/Cache_vs_Artifacts.md>)

> ⚠️ Practice answer, not verified. Some answers contain mistakes; when in doubt, follow the lesson.

## Answer

Artifacts in GitLab CI refer to files that a job generates and needs to share with other jobs within a pipeline. They allow us to pass information, data, or build artifacts from one stage of our CI/CD process to another. This is essential for maintaining the flow of necessary resources and ensuring each job can consume the outputs of previous ones.

#### Triaging the Question

The question is essentially asking you to explain what GitLab CI artifacts are and why they are critical when running multiple jobs in a pipeline. The key elements we need to cover include:

Definition: What an artifact is.
Purpose: Why artifacts are needed between jobs.
Common Use Cases: How and where artifacts fit into the CI/CD workflow.

#### First-Principles Solution

Artifacts in GitLab CI serve as a mechanism for job-to-job communication. Each job can produce files, which are then stored and passed on to subsequent jobs. This is particularly useful when a job's output needs to be consumed by another job or used in some way during the pipeline execution.

Definition:

An artifact in GitLab CI is essentially any file that is generated by a job as part of your build process. These files can include compiled binaries, test reports, logs, and more. When you configure a job to store its artifacts, these files are saved on the GitLab server after the job has completed.

Purpose:
Dependency Resolution: Artifacts ensure that downstream jobs have access to necessary outputs from upstream jobs.

#### Cons
istency Across Jobs: By passing artifacts between jobs, we maintain consistency in our build process. For example, if a test job needs the binaries produced by a previous build job, it can rely on these artifacts being available.
Debugging and Verification: Artifacts provide a way to inspect the state of a pipeline at any point, which is crucial for debugging issues or verifying that jobs are behaving as expected.
Common Use Cases:
Binary Releases: If you have a build job that compiles your application into binaries, these can be stored as artifacts and then used by subsequent jobs (like deployment jobs) to deploy the exact version of the binary.
Test Reports: A testing job might generate detailed test reports, which are valuable for understanding why certain tests failed or succeeded. Storing these reports as artifacts allows other jobs to access them if needed.
Log Files: Log files can provide insights into what happened during a specific job execution. If there's an issue with a particular build step, having logs stored as artifacts can help diagnose the problem.

#### Closing Summary
+ Common Mistakes/Follow-Ups

In summary, artifacts in GitLab CI are crucial for maintaining a smooth and reliable pipeline by allowing jobs to share necessary outputs. They provide dependency resolution, ensure consistency across different stages of your pipeline, and offer valuable debugging tools.

#### Common mistakes
include not setting up artifact storage correctly or forgetting that certain files need to be stored as artifacts. Always consider the dependencies between jobs when planning your CI/CD pipeline.

```yaml
stages:

build_job:
  stage: build
  script:
    - make build
  artifacts:
    paths:
      - binaries/

test_job:
  stage: test
  dependencies:
    - build_job
  script:
    - make test
  artifacts:
    reports:
      junit: tests/reports/*.xml

deploy_job:
  stage: deploy
  dependencies:
    - test_job
  script:
    - make deploy
```
