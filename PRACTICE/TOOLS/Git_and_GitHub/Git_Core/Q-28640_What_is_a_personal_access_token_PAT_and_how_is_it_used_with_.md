# What is a personal access token (PAT) and how is it used with GitHub?

**Difficulty:** Intermediate · **Levels:** Fresher, SDE-1, SDE-1/2, SDE-2/3 · [↑ Token Permissions](<../../../../TOOLS/Git_and_GitHub/Git_Core/Token_Permissions.md>)

> ⚠️ Practice answer, not verified. Some answers contain mistakes; when in doubt, follow the lesson.

## Answer

TL;DR Summary:

A Personal Access Token (PAT) in GitHub is a secure string of characters that acts as an authentication mechanism to grant API access without using your password. It's commonly used by developers and CI/CD pipelines to interact with repositories, perform operations like pushing code or creating pull requests.

#### Triage
What the Question Is Really Asking:

The question aims to understand how you use GitHub’s personal access tokens (PATs) for secure authentication in various development tasks. The interviewer will probe your knowledge on securing credentials and best practices around token management.

Step-by-Step Solution:

Understanding PAT:

A Personal Access Token is a short-lived, one-time-use authentication key that can be generated by a user with appropriate permissions.
Unlike passwords, which are often stored in plaintext or hashed in databases, tokens are typically short and easily manageable.

Generating a PAT:

Go to your GitHub account settings > Developer settings > Personal access tokens.
Click "Generate new token" and give it a descriptive name like “CI/CD Deploy”.
Set the expiry date; tokens can be made permanent but are often set with an expiration for security reasons.

Using PAT in Command Line:

Use git config --global credential.helper store to cache your credentials (optional, but recommended).
Alternatively, use the token directly with commands like:
SH
git clone https://<TOKEN>@github.com/username/repository.git
Or, for a Git HTTPS URL:
SH
git config --global url."https://<TOKEN>@github.com/".insteadOf "https://github.com/"

Using PAT in CI/CD Pipelines:

Store the token securely using environment variables or secret management tools like GitHub Secrets.

#### Example
YAML for a GitHub Actions workflow:
YAML
jobs:
  deploy:
    runs-on: ubuntu-latest
    env:
      GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    steps:
      - name: Checkout code
        uses: actions/checkout@v2
      - name: Deploy to production
        run: |
          echo "Deploying with token"

Security Best Practices:

Keep tokens short-lived.
Limit the permissions granted to each token.
Never share your personal access tokens publicly.

Token Management:

Regularly review and revoke tokens that are no longer needed.
Use tools like gh CLI or third-party apps for managing multiple tokens.

#### Closing Summary
+ Common Mistakes/Follow-Ups:

Managing credentials securely is crucial in software development, especially when dealing with continuous integration/continuous deployment (CI/CD) pipelines. A personal access token provides a secure method to authenticate API requests without compromising your main account password. Best practices include using short-lived tokens, limiting permissions, and regularly reviewing and revoking tokens.

#### Common mistakes
include:

Using the same token for multiple purposes.
Storing tokens in plaintext files or hard-coded into scripts.
Failing to revoke unused tokens promptly.

#### Follow-ups
might include:

How you handle token storage in a production environment.
Any additional security measures like multi-factor authentication (MFA) or using service accounts.
