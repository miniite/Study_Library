# Why do you need a personal access token or SSH key instead of a password to push your database scripts to GitHub?

**Difficulty:** Basic · **Levels:** Fresher, SDE-1, SDE-1/2 · [↑ Token Permissions](<../../../../TOOLS/Git_and_GitHub/Git_Core/Token_Permissions.md>)

> ⚠️ Practice answer, not verified. Some answers contain mistakes; when in doubt, follow the lesson.

## Answer

To understand why a personal access token (PAT) or an SSH key is preferred over using a password when pushing database scripts to GitHub, we need to consider several factors including security, ease of use, and performance.

Firstly, let's clarify what each method entails:

Password: You enter your username and password in the terminal every time you push code.
Personal Access Token (PAT): This is a unique token generated by GitHub for authentication purposes. It acts like a password but is more secure as it can be revoked or reset if compromised.
SSH Key: An SSH key provides a more secure and automated way to authenticate without needing a password each time.

#### Triaging the Question

The core of the question revolves around understanding the security implications, user experience, and performance trade-offs between using a password, a personal access token, and an SSH key for authenticating with GitHub.

#### First-Principles Solution

Security:

Password: Passwords can be easily forgotten or stolen if not managed properly.
Personal Access Token (PAT): PATs are more secure as they can have restricted permissions, meaning even if the token is compromised, it won't have access to sensitive parts of your account. Additionally, you can revoke a token at any time without affecting other credentials.
SSH Key: SSH keys provide an added layer of security because they are stored in the local machine and never transmitted over the network, making them harder to intercept.

User Experience:

Password: You have to enter your password each time you push code, which can be cumbersome for frequent pushes.
Personal Access Token (PAT): Requires manual entry of the token each time, but can be stored in a more secure manner than a plain text password.
SSH Key: Once set up, no password is required. The key is exchanged securely between your machine and GitHub’s servers.

Performance:

Password: Each push requires network communication to authenticate with the server.
Personal Access Token (PAT): Similar performance impact as a password but with enhanced security features.
SSH Key: Faster because it avoids the need for an additional authentication step, although initial setup might involve more steps.

#### Closing Summary
and Common Mistakes/Follow-Ups

In summary, while passwords can be used to push database scripts to GitHub, they are less secure and inconvenient compared to using a personal access token or SSH key. The former provides better security by allowing fine-grained control over permissions and the ability to revoke tokens if needed. On the other hand, an SSH key offers a seamless experience with enhanced security because it is stored locally.

#### Common mistakes
include:

Using passwords: They are less secure and inconvenient.
Not setting up SSH keys properly: Can lead to manual password entry or permission issues.

For follow-ups, you might be asked about specific scenarios where one method might be preferable over another. For example, in a highly secure environment, an SSH key might be the preferred option due to its security benefits.

**Code:**

```bash
# Example of setting up SSH key for GitHub
ssh-keygen -t rsa -b 4096 # Generate RSA key with 4096 bits
cat ~/.ssh/id_rsa.pub | ssh user@github.com "mkdir -p ~/.ssh && cat >> authorized_keys"
```
