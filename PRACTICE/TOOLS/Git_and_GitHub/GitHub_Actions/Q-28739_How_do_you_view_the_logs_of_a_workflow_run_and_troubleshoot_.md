# How do you view the logs of a workflow run and troubleshoot a failed step?

**Difficulty:** Basic · **Levels:** Fresher, SDE-1/2, SDE-2/3 · [↑ Workflow Fundamentals](<../../../../TOOLS/Git_and_GitHub/GitHub_Actions/Workflow_Fundamentals.md>)

## Answer

To troubleshoot a failed GitHub Actions workflow, you need to understand where the log files are stored and how to access them. Logs are crucial because they provide insight into what happened during each step of your workflow execution, helping you identify issues such as syntax errors, deployment failures, or environment-specific problems.

#### Triage
What's Being Probed

The interviewer is looking for your understanding of where logs reside in GitHub Actions and how to retrieve them. They might also want to know if you are familiar with common logging practices and how to interpret the log output effectively.

#### First-Principles Solution
Identify the Workflow ID: The first step involves identifying the specific workflow run that failed. You can do this by navigating to the "Actions" tab in your GitHub repository, selecting the relevant workflow from the list of runs, and clicking on the particular run you're interested in.
Access Log Files:
GitHub Actions Console: By default, GitHub stores logs for 30 days. You can access these logs directly through the web UI under the "Artifacts" section within a failed workflow's run page. The "Run details" tab provides links to view and download log files.
Using API or CLI: For more programmatic access, you can use GitHub Actions APIs or the gh command-line tool to retrieve logs programmatically.
Detailed Steps
Open the Workflow Run:

Navigate to your repository -> Click on "Actions" tab -> Select the relevant workflow from the list of runs.
Locate the Failed Step Logs:
In the run details, look for a section called "Artifacts" or "Run Details." Here you will find links to logs generated by each step.

Analyze the Logs:
Review the log files for error messages, stack traces, or any other hints that could indicate what went wrong.
Focus on identifying the step where the failure occurred and look at the logs leading up to it for context.

#### Closing Summary
+ Common Mistakes/Follow-Ups

By understanding how to access and analyze logs in GitHub Actions, you can effectively troubleshoot failed workflows. Common mistakes include not knowing where to find logs or interpreting them incorrectly. Always ensure that you are checking the correct workflow run and looking at the relevant step's logs.
