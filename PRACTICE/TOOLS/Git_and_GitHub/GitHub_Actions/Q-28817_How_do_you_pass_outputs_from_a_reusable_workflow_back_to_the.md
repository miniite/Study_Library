# How do you pass outputs from a reusable workflow back to the caller and what are the size and type limitations you have hit?

**Difficulty:** Intermediate · **Levels:** SDE-1/2, SDE-2/3 · [↑ Workflow Fundamentals](<../../../../TOOLS/Git_and_GitHub/GitHub_Actions/Workflow_Fundamentals.md>)

> ⚠️ Practice answer, not verified. Some answers contain mistakes; when in doubt, follow the lesson.

## Answer

When working with GitHub Actions, passing outputs from a reusable workflow back to the caller is essential for maintaining clean and modular workflows. This process involves defining an outputs section in your action's configuration file and then referencing these outputs appropriately within the calling context.

#### Triaging the Question

The question asks about how to pass outputs from a reusable workflow back to the caller, which is a common requirement when you need to share data between steps or workflows. The interviewer might be probing for understanding of the structure needed in your action's configuration and any limitations or considerations around passing this information.

#### First-Principles Solution

To pass outputs from a reusable GitHub Actions workflow, follow these steps:

Define Outputs: In the action.yml file of your reusable action, define the outputs you want to return using the outputs: section.
Reference Outputs: When calling the reusable workflow in another workflow, use the steps.outputs.<output_name> syntax to access the returned values.

Here's an example:

YAML
# my-reusable-action/action.yml
name: My Reusable Action
description: An action that generates output data
outputs:
  result: # The name of the output you will be returning. Use this as a variable in your caller.
    description: "The result generated by the action"

In the calling workflow, you would reference this output like so:

YAML
# main-workflow.yml
- name: Call Reusable Action
  uses: ./.github/actions/my-reusable-action # Path to your reusable action
  id: my_reusable_action_id

- name: Use Output from Reusable Action
  run: echo "The result is ${{ steps.my_reusable_action_id.outputs.result }}"
Common Size and Type Limitations
Output Size: There are no hard size limits for the outputs you can return, but very large output values might lead to performance issues or increased workflow execution time.
Data Types: The types of data you can pass as outputs include strings, numbers, booleans, arrays, and even objects (if serialized). However, complex object structures should be avoided if they can be easily broken down into simpler components.

#### Closing Summary

Passing outputs from a reusable GitHub Actions workflow to the caller is straightforward but requires careful configuration. Ensure you define your outputs correctly in the action.yml file of your reusable action and use them appropriately in the calling workflow.

#### Common Mistakes
and Follow-Ups
Not Defining Outputs: Not defining the outputs: section can result in missing or incorrectly structured data.
Incorrect Reference: Using incorrect syntax to reference outputs (e.g., not using ${{ steps.step_id.outputs.output_name }}) will cause your workflow to fail.
Overly Complex Data Structures: Passing overly complex data structures without proper serialization or breaking them down into simpler components can lead to performance issues.

By understanding these points, you ensure that your GitHub Actions workflows are robust and maintainable.
