# How would you migrate a legacy warehouse of stored procedures into dbt incrementally without a big-bang cutover?

**Difficulty:** Deep · **Levels:** Architect/Principal, SDE-1/2, SDE-2/3 · [↑ dbt Models and Runs](<../../../../TOOLS/dbt/dbt_Core/dbt_Models_and_Runs.md>)

## Answer

To migrate a legacy warehouse of stored procedures into dbt incrementally, we need to systematically refactor and re-engineer existing ETL logic while ensuring data consistency and minimal disruption. The core idea is to use incremental materializations in dbt to maintain the lineage and integrity of our data as we transition from stored procedures.

First, let's triage the question by breaking down what needs to be done:

Understand the Legacy System: Analyze existing stored procedures to understand their logic, dependencies, and performance characteristics.
Define a Migration Strategy: Plan how to incrementally move parts of the ETL process from stored procedures to dbt models.
Refactor Stored Procedures into dbt Models: Translate complex queries and logic into dbt models while maintaining data integrity.
Implement Incremental Materializations: Use incremental strategies in dbt to update only new or changed records, ensuring efficient updates without reprocessing entire datasets.

Now, let's dive into the solution from first principles:

#### Assumptions

The legacy warehouse uses SQL for stored procedures.
The target environment is a data lake or datawarehouse that supports dbt.
Incremental updates are feasible and supported by both the source and target systems.

Step-by-Step Solution:

Audit Legacy Procedures: Identify all critical stored procedures in use, noting their performance impact and dependencies.
SQL
-- Example: List of procedures to audit
SELECT procedure_name
FROM information_schema.routines
WHERE routine_type = 'PROCEDURE';
Create dbt Models: For each legacy stored procedure, create a corresponding dbt model. Start with simple transformations and gradually move complex logic.
YML
# Example: Create a dbt model for a legacy procedure
---
{{ config(materialized='incremental') }}

with source_data as (
  -- SQL query to fetch data from the source
)

select * from source_data
where ...
Implement Incremental Logic: Use dbt's incremental materialization type to handle updates efficiently. Ensure that only new or modified records are processed.
YML
# Example: Incremental logic in a dbt model
{{ config(materialized='incremental') }}

with source_data as (
  -- SQL query to fetch data from the source
)

select * from source_data
where _dbt_updated_at_column > current_date - interval '1 day'
Validate and Test: Continuously validate dbt models against their stored procedure counterparts. Use test cases to ensure that incremental logic handles edge cases correctly.
YML
-- Example: Tests in a dbt model
{% test equals_test, column_name %}
  assert equals(column_name, expected_value)
{% endtest %}
Monitor and Optimize: Monitor the performance of dbt models and optimize as needed. Use dbt Cloud for continuous integration and deployment.

#### Closing Summary
By incrementally migrating stored procedures to dbt, we ensure data consistency and maintain the integrity of our ETL processes. This approach allows for a smooth transition while minimizing downtime and risk.
