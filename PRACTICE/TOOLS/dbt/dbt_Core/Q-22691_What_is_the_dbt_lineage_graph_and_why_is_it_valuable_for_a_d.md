# What is the dbt lineage graph and why is it valuable for a data team?

**Difficulty:** Intermediate · **Levels:** Architect/Principal, Fresher, SDE-1/2, SDE-2/3 · [↑ dbt Fundamentals](<../../../../TOOLS/dbt/dbt_Core/dbt_Fundamentals.md>)

## Answer

TL;DR

The dbt lineage graph is a powerful feature that helps visualize how your data flows through various transformations, from source to target tables. It's invaluable for understanding dependencies and ensuring data integrity, making it easier to maintain and troubleshoot complex data pipelines.

#### Triage

This question focuses on the concept of the dbt lineage graph within the broader context of a data team's responsibilities. The interviewer is likely probing your understanding of how dbt works and its role in managing and tracking transformations, as well as the importance of lineage for maintaining data quality and integrity.

#### Assumptions
You are familiar with dbt (data build tool).
You understand basic concepts like models, sources, and dependencies in a data pipeline.
The team uses a structured approach to manage their data workflows.

#### First-Principles Solution

The dbt lineage graph is generated by running the dbt run command, which not only compiles your models but also creates a visual representation of how each model depends on other sources and intermediate models. Here’s a step-by-step breakdown:

Model Dependencies: When you define a model in dbt, it declares its dependencies on other models or sources. For example:
SQL
{{ config(materialized='table') }}
select *
from raw_customer_data
join transformed_orders
Graph Generation: Running dbt run generates an SVG file that shows these dependencies in a visual format. Each node represents a model, and the edges show the flow of data.
Visualization: The lineage graph can be viewed using tools like dbt Cloud or by opening the generated SVG directly.

#### Example
Model

Here’s a simple example to illustrate:

SQL
{% macro get_customer_orders() %}
    select c.customer_id,
           o.order_id
    from raw_customers c
    left join orders o on c.customer_id = o.customer_id
{% endmacro %}

{% macro transform_orders(customer_ids) %}
    select customer_id, order_id
    from {{ ref('get_customer_orders') }}
    where customer_id in {{ customer_ids|join(',') }}
{% endmacro %}

The lineage graph will show that transform_orders depends on get_customer_orders, making it clear how data flows through these transformations.

#### Closing Summary
and Common Mistakes/Follow-Ups

In summary, the dbt lineage graph is a critical tool for understanding and managing dependencies in your data pipelines. It helps in several ways:

Maintaining Data Integrity: Ensures that changes to upstream models are propagated correctly.
Troubleshooting: Quickly identifies where issues might be originating.
Documentation: Provides clear documentation of the data flow, aiding onboarding and knowledge sharing.

#### Common mistakes
include underestimating the complexity of large pipelines or failing to regularly update lineage diagrams as new dependencies are added. Follow-ups might explore how dbt handles incremental updates, schema changes, or integration with other tools like Airflow for orchestrating complex pipelines.
