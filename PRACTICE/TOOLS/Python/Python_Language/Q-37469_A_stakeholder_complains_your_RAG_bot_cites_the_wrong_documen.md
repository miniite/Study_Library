# A stakeholder complains your RAG bot cites the wrong document. How would you instrument the Python pipeline to attach and verify source attribution so a citation always maps to the chunk that produced the claim?

## Answer

To address the issue of the RAG (Retrieval-Augmented Generation) bot citing the wrong document, we need to instrument our Python pipeline with robust source attribution mechanisms. The key is to ensure that every claim generated by the model has a clear and traceable connection to its source documents. This involves tagging each chunk or sentence in the source documents with unique identifiers, tracking these tags through the processing pipeline, and finally verifying the integrity of these associations.

#### Triage

The core question here is about how to implement a robust tracing mechanism within a Python-based RAG system so that we can confidently associate any generated claim back to its original document. The interviewer likely wants to see an understanding of data provenance, error handling, and potentially even scalability concerns. We will make some key assumptions: the documents are structured as text files or JSON objects; the RAG model operates in a sequential manner, meaning chunks are processed one by one.

#### First-Principles Solution
Tagging Documents: Each document should be tagged with unique identifiers.
Chunking and Tagging: When processing documents into smaller chunks (e.g., sentences), these chunks must retain their source identifier.
Tracking Through Pipeline: Ensure that every chunk is passed through the pipeline while preserving its tag.
Verification Mechanism: Implement a verification step to ensure the claim matches the correct document chunk.
