# How do you find the actual SQL that your ORM (like Hibernate or Sequelize) sends, so you can check its indexes?

**Difficulty:** Intermediate · **Levels:** Architect/Principal, Fresher, SDE-1, SDE-1/2, SDE-2/3 · [↑ Reading EXPLAIN ANALYZE](<../../../../01_Databases_and_SQL/Query_Performance/Indexing/Reading_EXPLAIN_ANALYZE.md>)

## Answer

To find out the actual SQL generated by an Object-Relational Mapping (ORM) tool like Hibernate or Sequelize, we need to trace how the ORM translates our high-level query language into SQL. This is crucial for understanding and optimizing database performance, especially when dealing with complex queries. Here’s a step-by-step guide on how to do this:

Identify the Query: Start by identifying which part of your application makes the query you want to inspect.
Enable Logging: Most ORMs have logging features that can output the generated SQL statements.
Analyze the Generated SQL: Look at the actual SQL and understand how it translates into database operations.

Let's break this down further:

#### Triage
What is Being Probed

The question aims to understand how to inspect the SQL queries generated by an ORM, which involves knowledge of logging mechanisms in ORMs and understanding SQL query optimization. Assumptions include familiarity with the application structure and configuration of the ORM.

#### First-Principles Solution
1. Identify the Query Source

First, locate where the query is executed within your application. This could be a specific function or method that uses the ORM to interact with the database.

2. Enable Logging in the ORM

Most ORMs provide configuration options to enable logging. For Hibernate, you can do this by setting properties like hibernate.show_sql and hibernate.format_sql. In Sequelize, you can use logging: console.log when creating your Sequelize instance.

JAVASCRIPT

#### cons
t sequelize = new Sequelize('database', 'username', 'password', {
  logging: console.log,
  // other configurations...
});
3. Run the Application and Observe Logs

Run your application with the logging enabled. When you execute the query, it will output the generated SQL to the logs.

#### Example
Logging Output

If you are using Hibernate, the log might look something like this:

PLAINTEXT
SELECT * FROM users WHERE id = 123;

For Sequelize, the output would be similar:

PLAINTEXT
Executing (default): SELECT * FROM `users` WHERE `id` = 123 LIMIT 1;
Analyzing the Generated SQL

Once you have the generated SQL, analyze it to see if the ORM is using indexes effectively. Look for the presence of indexes in the query execution plan.

#### Common Mistakes
and Follow-Ups
Not Enabling Logging: Always ensure logging is enabled before running queries.
Ignoring Index Usage: Verify that the queries are leveraging available indexes. If not, consider adding appropriate indexes or optimizing your database schema.
Performance Issues: Even with correct indexing, poor query structure can still lead to performance issues.

#### Closing Summary

By enabling and inspecting ORM-generated SQL, you gain insights into how your application interacts with the database. This process is essential for ensuring efficient data retrieval and avoiding potential bottlenecks in complex queries.
