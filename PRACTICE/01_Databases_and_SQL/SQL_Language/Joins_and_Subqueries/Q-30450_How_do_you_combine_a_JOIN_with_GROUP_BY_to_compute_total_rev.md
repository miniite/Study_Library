# How do you combine a JOIN with GROUP BY to compute total revenue per customer?

**Difficulty:** Intermediate · **Levels:** Fresher, SDE-1, SDE-1/2 · [↑ Join Practice Problems](<../../../../01_Databases_and_SQL/SQL_Language/Joins_and_Subqueries/Join_Practice_Problems.md>)

## Answer

To compute the total revenue per customer using a combination of JOIN and GROUP BY, we need to follow these steps:

Summary: The task is to find the total revenue generated by each customer from their transactions. This involves joining a customers table with an orders table (or similar) based on the customer ID, grouping by the customer, and summing up the revenue.

#### Triage
The question essentially asks for two key pieces of information: how to join tables correctly and how to use GROUP BY along with an aggregate function like SUM. We will assume there is a customers table and an orders table in our database schema, where the orders table contains details about each transaction, including the customer ID (customer_id) and revenue amount (revenue).

#### First-Principles Solution

Join the customers and orders tables using the customer_id.
Use a GROUP BY clause to group the results by the customer.
Apply an aggregate function, such as SUM, on the revenue column to compute the total revenue for each customer.

Here's a step-by-step breakdown of how we can achieve this:

SQL
SELECT c.customer_id, c.customer_name, SUM(o.revenue) AS total_revenue
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name;
Step 1: We select the customer_id and customer_name from the customers table.
Step 2: We join the orders table on the common column customer_id.
Step 3: We group by both customer_id and customer_name to ensure unique rows for each customer.
Step 4: We use SUM(o.revenue) to calculate the total revenue per customer.

This query will return a list of customers along with their total revenue, sorted by total_revenue.

#### Closing Summary
+ Common Mistakes/Follow-Ups:
The common mistake is forgetting to include all necessary columns in the SELECT statement that uniquely identify each group (e.g., including both customer_id and customer_name).
Another pitfall is not using the correct aggregate function or applying it improperly. For instance, you might mistakenly use an aggregation on non-aggregated fields.
It's also important to ensure that your tables have appropriate indexes on foreign keys (e.g., customer_id) to improve query performance.

**Code:**

```sql
SELECT c.customer_id, c.customer_name, SUM(o.revenue) AS total_revenue
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name;
```
