# What is the difference between DISTINCT and GROUP BY when removing join duplicates?

**Difficulty:** Deep · **Levels:** Fresher, SDE-1, SDE-1/2 · [↑ Joins vs Subqueries and Join Types](<../../../../01_Databases_and_SQL/SQL_Language/Joins_and_Subqueries/Joins_vs_Subqueries_and_Join_Types.md>)

## Answer

To understand the difference between DISTINCT and GROUP BY in the context of removing join duplicates, let's first establish what each does.

#### Triaging the Question

The core of this question is to differentiate between using DISTINCT and GROUP BY when dealing with duplicate rows resulting from a join operation. Specifically, we need to understand how these clauses affect the result set differently, especially in terms of handling duplicates.

#### Assumptions
We are working within a SQL context where joins can produce duplicate rows.
The goal is to remove these duplicates based on specific columns.

#### Solution
DISTINCT Clause

The DISTINCT keyword in SQL ensures that each row returned from the query is unique, discarding any duplicates. When used after a join operation, it removes all duplicate rows regardless of how they were generated by the join. Essentially, DISTINCT acts as a filter on the entire result set.

For example:

SQL
SELECT DISTINCT col1, col2 FROM tableA JOIN tableB ON tableA.id = tableB.id;

This query will return unique combinations of col1 and col2, where duplicates are removed based solely on these columns. However, if there are other columns in the result set that contribute to duplicate rows, DISTINCT does not address them.

GROUP BY Clause

The GROUP BY clause is used for aggregation operations. It groups the rows of a result set by one or more columns and allows you to apply aggregate functions (e.g., COUNT, SUM) on other columns. When used with an aggregate function, it can help eliminate duplicates within specific groups.

For example:

SQL
SELECT col1, col2, COUNT(*) FROM tableA JOIN tableB ON tableA.id = tableB.id GROUP BY col1, col2;

In this case, GROUP BY is paired with a count function (COUNT(*)) to ensure that each combination of col1 and col2 is counted only once. The result will include unique combinations of col1 and col2, but it also provides aggregate information about the number of rows for each group.

#### Closing Summary

In summary, while both DISTINCT and GROUP BY can help remove duplicates from join operations, they do so in different ways:

DISTINCT: It removes all duplicate rows from the entire result set, providing unique combinations without considering any specific aggregate functions.
GROUP BY: It groups rows by specified columns and allows for the application of aggregate functions to provide summary information while ensuring uniqueness within each group.

#### Common Mistakes/Follow-Ups
Misunderstanding DISTINCT: Some developers might think that DISTINCT only applies to the selected columns, whereas it affects all columns in the result set.
Overusing GROUP BY: While useful for aggregations, using GROUP BY without aggregate functions can lead to errors or unexpected results.

Understanding these nuances is crucial when dealing with complex queries and join operations in SQL databases.
