# Explain how you would use presigned URLs so a client uploads large training samples straight to object storage instead of routing them through your ingestion service.

**Difficulty:** Intermediate · **Levels:** Architect/Principal, SDE-1/2, SDE-2/3 · [↑ Presigned URLs](<../../../../06_Cloud_Computing/Cloud_Foundations/Cloud_Fundamentals/Presigned_URLs.md>)

## Answer

To explain how I would use presigned URLs for clients to upload large training samples directly to object storage, let's start by understanding what a presigned URL is and why it’s useful in this context. A presigned URL is a special type of URL generated by the server that can be used to perform specific actions on an object stored in cloud services like AWS S3 or Azure Blob Storage without needing your API keys or authentication credentials.

The main advantage of using presigned URLs for large file uploads is reducing the load on our ingestion service and optimizing the upload process. Instead of clients sending files through a central service, which could become a bottleneck, they can directly upload to object storage, making the system more scalable and efficient.

Generate Presigned URLs:
On the server-side, we generate presigned URLs using our cloud provider SDKs. This URL is valid for a certain period and can be used by clients to upload files directly.
Client-Side Implementation:
The client application requests a presigned URL from the server.
Upon receiving the URL, the client uses this URL in an HTTP POST request to upload the file.

```javascript
async function uploadFile(file) {
  const {name} = file;
  const presignedUrl = await fetch('/api/generate-presigned-url', {
    method: 'POST',
    body: JSON.stringify({filename: name})
  }).then(res => res.json()).then(url => url.url);

  const formData = new FormData();
  formData.append('file', file);

  // Upload the file to S3 using the presigned URL
  await fetch(presignedUrl, {
    method: 'PUT',
    body: formData
  });
}
```
