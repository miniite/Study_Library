# How do you govern the data lineage of derived telemetry (rolled-up metrics, sampled traces) so an AIOps model's decisions can be traced back to the raw signals despite aggregation and sampling?

**Difficulty:** Deep · **Levels:** Architect/Principal, SDE-2/3 · [↑ Explainability and Data Access Trade-offs](<../../../../11_AI_and_ML/Responsible_AI/AI_Governance/Explainability_and_Data_Access_Trade-offs.md>)

## Answer

To ensure that AIOps models' decisions are traceable back to their original telemetry data, we need a robust system of AI governance focused on data lineage. This involves documenting how derived metrics (rolled-up metrics and sampled traces) are generated from raw signals, ensuring transparency in the transformation processes, and maintaining audit trails for compliance and accountability.

The question is probing our understanding of several key aspects:

Data Transformation Processes: How telemetry data undergoes aggregation and sampling to form rolled-up metrics.
Traceability: The ability to trace model decisions back to specific raw signals.
Audit Trails: Maintaining records that can be referenced for verification or validation purposes.

We'll assume the following:

Raw telemetry data is generated by various sources, such as network devices, servers, and applications.
Aggregated metrics are derived from this raw data through statistical or analytical processes.
Sampled traces provide insights into specific instances of events within a larger dataset.

To solve this problem, we need to break it down step-by-step:

Step 1: Define Data Lineage

Data lineage involves tracking the flow of data through different stages. For AIOps, we need to document each transformation and its relationship with raw signals.

#### Example

Suppose we have a system generating network traffic metrics (packets per second). This raw signal is aggregated into daily summaries and sampled for anomaly detection. We need to maintain records of these transformations:

Raw Telemetry: Packets per second from various devices.
Aggregated Metrics: Daily summaries of packets per second.
Sampled Traces: Instances where packet loss exceeds a certain threshold.
Step 2: Implement Data Transformation Pipelines

Each step in the data processing pipeline should be clearly documented. This includes:

Data Ingestion: Capture raw telemetry from sources.
Preprocessing: Apply filtering, normalization, and other transformations before aggregation or sampling.
Aggregation & Sampling: Create summary metrics and select representative samples for analysis.
Step 3: Use Metadata

Metadata is crucial in maintaining data lineage:

Transformation Logs: Log the specific transformations applied to each piece of raw data.
Sampling Criteria: Document the rules used for selecting sampled traces.
Version Control: Keep track of different versions of models and their corresponding data pipelines.
Step 4: Maintain Audit Trails

Audit trails provide a historical record that can be referenced:

Event Logs: Record when specific events (e.g., anomalies detected) occur.
Model Outputs: Store outputs from each model run, linking them back to the raw telemetry data.
User Actions: Track user actions and changes made to the system.
Step 5: Traceability Tools

Implement tools that enable tracing of decisions:

Data Flow Diagrams: Visualize how data moves through the system.
Query Interfaces: Allow queries into the transformation logs and metadata for detailed inspection.
API Endpoints: Provide APIs for accessing audit trails and lineage information.
Step 6: Compliance & Validation

Ensure that our governance practices meet regulatory requirements:

Regulatory Standards: Follow industry standards like GDPR, HIPAA, etc., if applicable.
Validation Testing: Regularly test the system’s ability to trace decisions accurately.
Continuous Improvement: Periodically review and update governance policies based on new insights or changes in regulations.

#### Closing Summary

By implementing a robust data lineage strategy focused on transparency, accountability, and compliance, we can ensure that AIOps model decisions are fully traceable back to their original raw signals. This involves defining clear data transformations, maintaining thorough metadata, and using tools to enable easy tracing of events and decisions.

#### Common Mistakes/Follow-Ups
Overlooking Raw Data: Failing to maintain access to the original raw telemetry data.
Insufficient Documentation: Not keeping detailed records of each transformation step.
Lack of Audit Trails: Missing out on maintaining logs for every significant event and action.
Inadequate Traceability Tools: Relying solely on manual processes or insufficient tools.
