# How do ingestion tools authenticate to sources (API keys, OAuth, database credentials)?

**Difficulty:** Basic · **Levels:** Fresher, SDE-1/2, SDE-2/3 · [↑ Ingestion Credentials](<../../../../02_Data_Engineering/Pipelines_and_Integration/Data_Ingestion/Ingestion_Credentials.md>)

## Answer

To understand how data ingestion tools like Airbyte and Fivetran authenticate to their sources, let's break down the process step by step from first principles. This is crucial because it ensures secure and reliable access to your data systems. The key points of authentication include API keys, OAuth tokens, and database credentials.

Firstly, when a data ingestion tool needs to access a source such as an API or a database, it requires some form of identification to prove its legitimacy. For example, using API keys is a common method where a unique identifier is provided by the service provider to the ingestion tool. In contrast, OAuth tokens are more complex and involve multiple steps to authenticate a user or application.

Let's dive into the detailed process:

Authentication Mechanisms
API Keys: These are simple, static credentials used for accessing APIs. They can be generated through the API provider’s interface and are often stored securely on the ingestion tool side.
OAuth Tokens: This involves more complexity and security measures. It includes steps like obtaining an access token via authorization code flow or client credentials flow.
Step-by-Step Authentication
Using API Keys
The data engineer generates an API key in the source system’s settings.
The ingestion tool is configured with this API key during setup.
Each request to the API includes the API key as a header or parameter, proving identity and authorization.
Using OAuth Tokens
The ingestion tool initiates an OAuth flow by requesting permission from the user or application owner.
The source system redirects the user to its authentication page where they log in.
Upon successful login, the source system grants an access token to the ingestion tool.
The token is then used for subsequent API requests.
Security Considerations
API Keys: While easy to implement, they can be harder to manage and less secure if not handled properly. Storing them as plaintext or hardcoding in the application is a security risk.
OAuth Tokens: They offer better security because tokens have limited validity periods and can be revoked. However, they require more setup and handling of secret credentials.
Practical Example

Let's consider a simple example using API keys for a RESTful API source:

PLAINTEXT
curl -X GET "https://api.example.com/v1/data" \
-H "Authorization: Bearer <API_KEY>"

In this case, <API_KEY> is the key generated by the API provider and stored securely in the ingestion tool’s configuration.

#### Common Mistakes
and Follow-Ups
Mistake: Storing sensitive keys like API keys or OAuth tokens in plain text. This can lead to unauthorized access.

#### Follow-Up
Best practices include using secure storage mechanisms, rotating keys regularly, and implementing logging and monitoring for suspicious activity.

In summary, the choice of authentication method depends on the specific requirements and security needs of the data source and ingestion tool. Understanding these mechanisms ensures robust integration and protection of sensitive data.
