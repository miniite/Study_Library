# How do you govern the sensitivity classification of tool outputs, so an agent that fetches confidential data can't then surface it via an unprotected channel?

**Difficulty:** Expert · **Levels:** Architect/Principal, SDE-2/3 · [↑ Governing Incident Data Reuse](<../../../../05_Data_Governance_and_Security/Governance/Data_Strategy/Governing_Incident_Data_Reuse.md>)

> ⚠️ Practice answer, not verified. Some answers contain mistakes; when in doubt, follow the lesson.

## Answer

To effectively govern the sensitivity classification of tool outputs and prevent agents from surfacing confidential data through unprotected channels, we need to establish a robust strategy involving data tagging, access controls, encryption, and monitoring mechanisms. This approach ensures that only authorized personnel can access sensitive information and that data is handled securely throughout its lifecycle.

#### Triaging the Question

The core of this question revolves around ensuring data confidentiality when using AI tools or agents. The interviewer is probing your understanding of data governance best practices, including tagging, encryption, and monitoring mechanisms to prevent unauthorized exposure. Key assumptions include:

The system uses some form of classification for sensitive data.
There are defined roles with varying levels of access.
The goal is to maintain data integrity and confidentiality.

#### Solution

Data Tagging: Implement a metadata tagging system that labels data based on sensitivity (e.g., public, internal, confidential). This tagging can be done using tags like "confidential" or "restricted."

Access Controls: Define access policies that restrict sensitive data to authorized users and systems. Use role-based access control (RBAC) to ensure only appropriate roles can interact with sensitive data.

Encryption: Encrypt sensitive data both at rest and in transit. This ensures even if an agent fetches confidential data, it remains unreadable without the encryption key.

Monitoring: Implement logging and monitoring mechanisms to track who accesses which data and under what circumstances. Use tools like SIEM (Security Information and Event Management) systems for real-time alerting on suspicious activities.

Data Masking: For outputs that need to be shared with non-sensitive users, implement data masking techniques to hide or replace sensitive information while preserving the utility of the output.

Regular Audits: Conduct regular security audits and vulnerability assessments to ensure compliance with data governance policies and identify potential weaknesses.

#### Example
Workflow
Data Tagging: Label all data as "confidential" before it is ingested by any AI tool.
Access Request: An agent requests data, which triggers an access control check against the RBAC policy.
Authorization Check: The system checks if the requesting agent has the appropriate role (e.g., "data analyst" with limited access).
Data Retrieval: If authorized, the data is retrieved and encrypted for transmission.
Data Handling: In the AI tool, the data remains in an encrypted state unless explicitly decrypted by a trusted service.
Output Generation: The output generated by the AI model is checked against masking rules to ensure no sensitive information is exposed.

#### Closing Summary

By implementing a comprehensive strategy that includes data tagging, access controls, encryption, monitoring, and regular audits, we can effectively govern the sensitivity classification of tool outputs. This ensures that agents cannot surface confidential data via unprotected channels, maintaining the integrity and confidentiality of sensitive information.

```python
# Example of a simple access control policy check in Python
def has_access(user_role, required_role):
    return user_role == required_role

user_role = "data_analyst"
required_role = "admin"
if has_access(user_role, required_role):
    print("Access granted")
else:
    print("Access denied")
```
