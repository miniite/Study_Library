## Answer

You are given two integers, left and right, each lying within a small bounded range that may include negative values, zero, and positive values. Return their arithmetic sum, left + right.

The result should be exact — no wrapping, clamping, or rounding — just the ordinary integer sum of the two inputs.

Input

left: an integer with -100 <= left <= 100.
right: an integer with -100 <= right <= 100.

Output

A single integer equal to left + right.

#### Cons
traints

-100 <= left, right <= 100

#### Example
s & test cases
TEXT
Input: left = 7, right = 25 -> Output: 32
Why: Two positive values add normally.

Input: left = -40, right = 15 -> Output: -25
Why: A negative and a positive combine to a negative result.

Input: left = -100, right = -100 -> Output: -200
Why: Both at the minimum bound; verifies the most negative possible sum.

Input: left = 100, right = 100 -> Output: 200
Why: Both at the maximum bound; verifies the most positive possible sum.

Input: left = 0, right = 0 -> Output: 0
Why: Additive identity edge case.

Input: left = 63, right = -63 -> Output: 0
Why: Opposite values cancel to zero.

#### Approach

Direct application of the addition operator on the two operands. With inputs bounded by +/-100 the sum fits comfortably in a standard 32-bit signed integer, so no overflow handling is required. The underlying "pattern" is simply exact arithmetic; if the + operator were disallowed, the same result could be built with bitwise XOR (sum without carry) plus a shifted AND (carry) iterated until the carry becomes zero.

Complexity

Time: O(1) — a single addition. Space: O(1) — no auxiliary storage is used.
