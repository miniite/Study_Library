# Design a chargeback/showback system so each team sees the true cost of the infrastructure they consume. How do you attribute shared costs (a common database, the mesh, logging) fairly, and how does this change team behavior?

## Answer

To design a chargeback/showback system that accurately attributes shared costs among different teams in an organization, we need to ensure fair cost allocation while also incentivizing efficient resource usage. The core idea is to track and attribute costs based on actual consumption, while using a mix of direct and indirect cost models.

First, let's break down the requirements and assumptions:

Teams are consuming various types of infrastructure resources (compute, storage, network).
Shared resources like databases, logging systems, and mesh networking must be accounted for.
The goal is to ensure that teams can see their true costs, which influences resource allocation decisions.

Now, let's detail the steps from first principles:

Data Collection: Implement mechanisms to collect detailed usage data for each team and shared resource. This includes metrics such as CPU hours, storage bytes used, network bandwidth, etc.
Shared Resource Modeling: Develop models to attribute costs of shared resources based on their consumption patterns. For example, a database might charge teams based on the number of queries or write operations they perform.
Cost Allocation Engine: Create an engine that processes usage data and applies the cost allocation rules to determine each team's share of the total cost.
Reporting Interface: Design a user-friendly interface for teams to view their costs, with detailed breakdowns of direct and shared resource consumption.
Detailed Steps

Data Collection:

Use cloud provider APIs or custom metrics collectors to gather usage data.
Ensure high-frequency sampling (e.g., every hour) to capture short-term spikes in usage.

Shared Resource Modeling:

For databases, model costs based on read/write operations and storage used.
For networking (mesh), charge teams based on their bandwidth consumption.
Logging systems can be charged based on the volume of logs generated by each team.

Cost Allocation Engine:

Implement a rules-based engine that applies different cost allocation formulas to shared resources.
Use proportional sharing for some services, where costs are distributed based on usage ratios.
For others, consider SLA-driven models, where teams pay more if they exceed agreed-upon thresholds.

Reporting Interface:

Develop a dashboard showing each team’s total cost and breakdown of direct and shared resources.
Provide historical data to show trends over time, helping teams optimize their resource usage.

#### Closing Summary

By accurately attributing costs, we can influence behavior towards more efficient use of infrastructure resources. This system not only provides transparency but also encourages teams to be mindful of their consumption patterns. However, the design must be flexible enough to accommodate different organizational needs and resource types.

#### Common Mistakes/Follow-Ups
Overlooking Indirect Costs: Teams might focus too much on direct costs while neglecting indirect benefits.
Inadequate Data Granularity: Insufficient detail in usage data can lead to unfair cost allocations.
Resistance to Change: Teams may resist the shift towards shared costing, viewing it as an additional burden.

def allocate_cost(usage_data, cost_rules):
    total_cost = 0
    for team, usage in usage_data.items():
        cost = sum([rule.calculate_cost(usage) for rule in cost_rules])
        total_cost += cost
        # Apply rules and update each team's cost
    return total_cost
