# How would you ensure a REST API is testable and mockable during frontend development?

**Difficulty:** Intermediate · **Levels:** Fresher, SDE-1, SDE-1/2, SDE-2/3 · [↑ Authorization Design](<../../../../07_Distributed_Systems_and_Design/APIs/REST_APIs/Authorization_Design.md>)

## Answer

To ensure a REST API is testable and mockable during frontend development, we need to design our APIs in a way that they can be easily consumed by frontends without exposing sensitive information or business logic directly. The key aspects include proper URL structure, HTTP methods usage, clear documentation, and the use of environment-specific configurations. This ensures that both backend and frontend teams can work independently while still maintaining a coherent system.

#### Triaging the Question

The question is asking how to make REST APIs robust for integration with frontends during development. The interviewer is probing into your understanding of API design principles, testing practices, and the ability to manage dependencies between backend and frontend developers effectively. Key assumptions include the use of a modular architecture, versioning of APIs, and the need for flexibility in testing environments.

#### First-Principles Solution

Clear URL Structure: Use meaningful URLs that reflect the resource being accessed. For example:

PLAINTEXT
GET /api/users/:userId => Fetches user information by ID.
POST /api/users => Creates a new user.
PUT /api/users/:userId => Updates user information by ID.
DELETE /api/users/:userId => Deletes a specific user.

HTTP Method Usage: Ensure that each endpoint uses the appropriate HTTP method (GET, POST, PUT, DELETE) based on its intended function.

Mocking and Testing Setup:

Use environment-specific configuration files to manage API endpoints and credentials. For example, in a .env file:
PLAINTEXT
REACT_APP_API_URL=http://localhost:8000/api
Implement API stubbing using tools like mock-service for Node.js or similar frameworks.
Write unit tests for your frontend components that interact with the API. Tools like Jest and React Testing Library can help here.

Documentation and Autogenerated Clients: Maintain clear documentation (e.g., using Swagger or OpenAPI) to ensure both backend and frontend teams are aligned on endpoint functionality. Generate client libraries from these documents if possible, making it easier for developers to consume the API.

Error Handling: Define consistent error handling strategies that can be caught by frontends. Use HTTP status codes appropriately (e.g., 401 for unauthorized access, 403 for forbidden actions).

#### Closing Summary
+ Common Mistakes/Follow-Ups

By following these guidelines, you ensure that the API is both testable and mockable during frontend development. Common mistakes include over-complicating URL structures or using complex methods unnecessarily. Always aim for simplicity and clarity.

For follow-ups, an interviewer might ask about specific tools used for mocking (like nock), how you handle rate limiting and authentication, or how you manage to keep your documentation up-to-date with the API changes.

```bash
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import App from '../App';

describe('User creation form', () => {
  beforeEach(() => {
    jest.mock(process.env.REACT_APP_API_URL);
  });

  test('creates a new user when submitted', async () => {
    render(<App />);
    const createUser = screen.getByRole('button', { name: /create/i });
    userEvent.click(createUser);

    // Assuming the API returns some kind of response
    expect(fetch).toHaveBeenCalledWith(process.env.REACT_APP_API_URL, { method: 'POST' });
  });
});
```
