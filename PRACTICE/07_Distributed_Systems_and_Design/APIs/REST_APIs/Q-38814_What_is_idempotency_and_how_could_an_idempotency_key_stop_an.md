# What is idempotency, and how could an idempotency key stop an expensive LLM generation from running twice if a user double-clicks send?

**Difficulty:** Intermediate · **Levels:** Fresher, SDE-1/2, SDE-2/3 · [↑ Idempotent POST Requests](<../../../../07_Distributed_Systems_and_Design/APIs/REST_APIs/Idempotent_POST_Requests.md>)

## Answer

Idempotency is a property of certain operations in mathematics, computer science, and network engineering where performing the operation multiple times has the same effect as performing it once. In the context of REST APIs, idempotent methods ensure that sending the same request more than once will have no side effects beyond those of a single execution.

In this scenario, if a user double-clicks to send an LLM (Large Language Model) generation request, we want to prevent unnecessary and expensive computations. An idempotency key can help achieve this by ensuring that only the first request is processed, while subsequent identical requests are simply ignored or handled efficiently.

Let's break down how to implement this:

Understanding Idempotency in API Design:

GET, HEAD, PUT (with a specific condition), and DELETE methods are idempotent.
POST should typically not be idempotent as multiple identical requests might result in different outcomes.
For our LLM generation use case, we need to ensure that the same request does not trigger multiple expensive computations.

Introducing an Idempotency Key:

An idempotency key is a unique identifier associated with each API request. This could be generated by a client (e.g., a UUID) and sent alongside the request.
On the server side, we can use this key to check if the operation has already been performed.

#### Implementation
Steps:

When a user sends an LLM generation request, generate or retrieve an idempotency key and include it in the headers or payload of the request.
The server receives the request and checks its database for an existing entry with that idempotency key.
If no entry exists, process the request as normal (e.g., trigger LLM generation).
Store the idempotency key and details about the request in a cache or database to track future requests.

#### Closing Summary
and Common Mistakes:
Using an idempotency key can significantly enhance the reliability and efficiency of API interactions, especially in scenarios where requests might be sent multiple times.
A common mistake is not properly checking for existing entries before processing a request, which could lead to unnecessary computations.
Another pitfall is forgetting to cache or store responses effectively, leading to increased load on your system.

By implementing idempotency correctly, you ensure that the LLM generation process is only triggered once per unique user intent, even if they double-click send multiple times. This improves both performance and resource utilization while maintaining the integrity of data processing.
